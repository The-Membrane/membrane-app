# services/chain — the EVM chain-client seam

Architecture rule (from `docs/EVM_MIGRATION.md`): **pages and components never import
viem/wagmi primitives directly.** All chain access flows:

```
components/pages → domain hooks (hooks/*)
                → services/chain/*   (one module per contract; typed via contracts/abis)
                → viem publicClient  (reads — wallet-independent, see client.ts)
                → wagmi walletClient (writes only)
```

Conventions (carried over from the Cosmos service layer — see the
`hook-query-patterns` skill):

- Services take `PublicClient | null` and **return null on failure, never throw**.
- Optional address override param; fallback via `config/evm/contracts.ts`.
- Reads must work with no wallet connected — full app visibility is a product requirement
  (`docs/audits/02-wallet-gating-routes.md`).
- ABIs are generated by `pnpm sync-abis` from membrane-solidity's Foundry `out/` into
  `contracts/abis/` (`as const`, so viem infers full call/return types).
- Hooks wrap services in React Query with primitive-only query keys, an `enabled` gate,
  and an explicit staleTime tier.

Migration map (Cosmos → EVM):

| Cosmos | EVM |
|---|---|
| `helpers/cosmwasmClient.tsx` | `services/chain/client.ts` |
| `contracts/codegen` + `contracts/generated` | `contracts/abis/` via `pnpm sync-abis` |
| `services/*.ts` `queryContractSmart` | `services/chain/<contract>.ts` `readContract` |
| `hooks/useWallet.ts` (cosmos-kit `useChain`) | same file, wagmi `useAccount`/`useConnect` internals |
| `hooks/useTransaction.ts` (sign+broadcast) | same shape over `walletClient.writeContract` + `waitForTransactionReceipt` |
| `hooks/useSimulate.ts` (StdFee estimation) | viem `simulateContract` + EIP-1559 estimation |
| `config/chains.ts`, `config/gas.ts` | `config/evm/chains.ts` (gas config deleted) |
| `config/contracts.json` bech32 book | `config/evm/contracts.ts` |

Reference implementation: `cdp.ts` in this directory.
