# scrvUSD NOW schedule publication boundary

This research-only layer makes a **future observation plan** durable and supplies separate attempt, run, and score receipts. It does not itself measure executable exit ability or establish a forecast. Existing v1 NOW issues remain unbound.

## Publication

The first-install migration in `scripts/apply-scrvusd-now-schedule-ddl.mjs` atomically creates three append-only tables and three narrow functions: manifest, confirmation, and visibility witness. It requires an existing dedicated publisher role, creates no role or grant, and refuses to install over an existing partial boundary. The manifest table has a GiST exclusion constraint for overlapping half-open windows. A duplicate SHA is rejected.

The publisher function reconstructs the exact JS unsigned manifest text from the fixed grid, then compares bytes before insertion. It also requires canonical UTC millisecond strings for the three top-level times. Equivalent JSON with reordered keys or offset timestamp notation cannot occupy a schedule window and later fail canonical readback.

`createPgNowScheduleStore(pool).publishFuture({startAtUtc,endAtUtc})` uses a **database clock** to create the canonical hourly manifest for the fixed holder, 1,000 crvUSD direct withdrawal route and 1h/2h/24h/7d arms. The publishing function validates the seal and fixed grid, uses its own server clock and transaction ID, and requires at least two hours of lead before the first slot.

After the manifest transaction commits, a second transaction reads it and stores a distinct confirmer transaction ID and server timestamp, still at least two hours before the first slot. A fresh read-only transaction verifies that committed confirmation. A third write transaction reads the committed manifest and confirmation, stamps `manifest_visible_at` with the DB clock, and records a distinct witness XID no later than first slot minus two hours. Fresh readback validates the exact witness. `publishFuture` returns this witnessed proof; `reconcileFuture(sha)` can finish a publication whose confirmation or witness acknowledgment was lost. These server timestamps are statement times, not COMMIT times. The witness stamp proves the manifest and confirmation were already committed when read; it is not the witness row's exact first visibility time.

The returned object adds `manifestVisibleAtUtc` and `witnessXid` to `manifest`, `manifestSha256`, `persistedAtUtc`, `confirmedAtUtc`, `publisherXid`, and `confirmerXid`. `historicalPublicationAvailabilityCertified:true` applies to the committed manifest and confirmation proven by the witness; it does not certify historical attempt state. `prospectiveScheduleConfirmed:true` means only the plan was prepublished. `runCoverageConfirmed:false` and `calibratedForecastEligible:false` remain explicit.

## Role boundary

The migration requires a privileged migration connection in `SCRVUSD_SCHEDULE_MIGRATION_DATABASE_URL` and `SCRVUSD_SCHEDULE_PUBLISHER_ROLE`. The migration login must differ from the publisher role. An administrator must independently provision the dedicated login role, grant USAGE on `public`, SELECT on the three base schedule tables (including `scrvusd_now_manifest_visibility`), and EXECUTE on the three base functions (including `witness_scrvusd_now_manifest(text)`). After all three migrations, grant SELECT on twelve protected tables and EXECUTE on the twelve exact functions in `FUNCTION_SIGNATURES`. Do not grant direct table writes, schema/database CREATE, ownership membership, or broad function EXECUTE. Neon PostgreSQL 18 may automatically grant the creating login membership in the newly created publisher role. The preflight permits either no inbound members or exactly one: the migration login, with `admin_option=true`, `inherit_option=false`, and `set_option=false`. Runtime audits permit that same exact membership only when its member is the single common owner of every installed protected table/function. Any other member, changed flag, mixed owner, or partial installation fails. This membership does not let the publisher inherit or set the owner role; the publisher must still fail direct-write, ownership-membership, and CREATE checks. The runtime pool uses the dedicated role; every session runs the read-only `SCRVUSD_SCHEDULE_AUDIT_SQL` first.

```text
node scripts/apply-scrvusd-now-schedule-ddl.mjs --apply
node scripts/apply-scrvusd-now-schedule-ddl.mjs --audit-publisher
```

The scripts do not print connection strings. No live migration, role provisioning, publication, or dedicated-role runtime audit has run. On the configured Neon PostgreSQL 18.6 database, a rollback-only transaction executed the current 50 migration SQL statements (14 base, 20 attempt, 16 as-of). The resulting 12 tables and 12 functions were inspected inside that transaction; a later read-only check found no installed role or tables. Preflight and owner-audit SQL was exercised on the earlier pre-witness revision, so it must be rerun for the current migration before installation. This checks SQL execution under the owner login, not the publisher login or a live slot. The fake session adapter also has focused offline tests. Inspect the target database, grants, function ownership, and prior artifacts before running the first-install migration.

## Next boundary

The additive `--apply-attempts` migration installs a second, independently guarded attempt boundary over an existing manifest installation. It refuses an absent base, a base owned by a different migration login, or any partial prior attempt schema. The same owner is required across base and attempt objects for the restricted creator membership to remain auditable. It runs transactionally, creates no role or grant, and does not replace old manifest rows or functions. Provision SELECT on the five new tables and EXECUTE on the five new functions to the **same audited dedicated role**, then run `--audit-attempts`. Once installed, the base publisher audit also checks direct writes, owner membership, and exclusive EXECUTE grants across all attempt tables/functions; before installation, absent optional attempt objects are filtered out. A leaked attempt grant therefore fails the base audit as well.

```text
node scripts/apply-scrvusd-now-schedule-ddl.mjs --apply-attempts
node scripts/apply-scrvusd-now-schedule-ddl.mjs --audit-attempts
```

`createPgNowAttemptStore(pool)` supplies an operational sequence for one hourly slot:

```text
committed manifest-visibility witness → four exact local start receipts
→ four server-timed START COMMITs
→ separate four-start confirmation COMMIT
→ separate capture-floor COMMIT and readback
→ collect shared source data after sourceCaptureFloorUtc
→ four arm RESULT COMMITs → separate full-run confirmation COMMIT/readback
```

Each start stores the full canonical local receipt TEXT and checks both the logical SHA and the physical SHA of the newline-terminated bytes. The server timestamps only a currently open half-open slot from a confirmed future manifest whose visibility witness has committed and has a server stamp no later than first slot minus two hours. Unique keys reject retries for a cell and reuse of a start receipt across cells. Start confirmation requires all four committed starts; the capture floor reads that committed confirmation in another transaction. The runner **must wait for the returned `sourceCaptureFloorUtc` before any quote, holder, duration, or flow collection**. The public v2 verifier checks each source `captureStartUtc` against the later DB source-start gate, while recognizing that RPC capture timestamps are local and self-reported. A local start time alone is insufficient.

Results have `issued`, `abstained`, `failed`, or `unknown` plus a restricted reason. An issued row stores full local v2 issue bytes and exact logical/physical SHA; SQL checks its manifest, slot, arm, and start receipt hashes. Issued rows also require the committed source-start receipt from the as-of migration and a local issue time at or after that receipt; install all three migration phases before live issued results. Non-issued operational rows retain their separate path. Results require a committed capture floor and must commit inside the slot. Unique issue hashes prevent cross-slot reuse. A run confirmation reads four committed results in a distinct transaction before any issued horizon target. Readback exposes missing starts, missing results, and an unconfirmed run separately. Its `runCoverageConfirmed` means **operational record completeness**, not a verified exit observation.

The result store labels issued rows `db_reported_issued_unverified`. Its retained bytes and server timing cannot independently prove RPC source truth, exact source capture chronology, or exit success. `calibratedForecastEligible` remains false. The opt-in v2 runner, public issue verifier, scorer, retrospective evaluator, and separate witnessed label reader now exist, but no live PostgreSQL migration, dedicated-role audit, or slot execution has run. A rollback-only owner-session SQL check and fake-session tests do not establish live cohort coverage. Historical as-of evaluation uses durable run and score visibility witnesses; see `scrvusd-v2-asof-receipt-design.md`.

## Additive as-of receipts API

`--apply-asof` installs four append-only receipt tables and four narrow functions after the base and attempt boundaries. Provision SELECT on `scrvusd_now_source_starts`, `scrvusd_now_run_visibility`, `scrvusd_now_scores`, and `scrvusd_now_score_visibility`, plus EXECUTE on `start_scrvusd_now_source`, `witness_scrvusd_now_run`, `record_scrvusd_now_score`, and `witness_scrvusd_now_score` to the audited publisher role; grant no direct writes. Run `--audit-asof` after provisioning. Existing base and attempt audits inspect installed as-of objects for direct writes and broad function grants.

`createPgNowAsOfStore(pool)` exposes `startSource`, `readSourceStart`, `witnessRun`, `readRunWitness`, `recordScore`, `witnessScore`, `readScoreWitness`, `listWitnessedCohort`, and `listPublishedSlotCensus`. Writes commit before fresh read-only receipt readback. Source start returns a server-timed nonce gate for the runner; it does not independently time RPC collection. Run visibility is stamped after a committed four-arm confirmation is read and before the earliest issued target. `recordScore` reads the exact existing issue and score files by `issueFilename` (with optional `issueOut` and `scoreOut` directories) before binding their bytes to the issued arm. The DB function requires the committed issue's target, capture deadline, holder, size, and route to match the score, requires a canonical UTC millisecond score time and known point status, and refuses recording until the capture deadline has passed on the DB clock. The scorer replays sealed quote and holder evidence before calling `recordScore`; SQL admission alone does not replay that evidence. Score visibility is stamped after the committed score is read in a distinct transaction. An unwitnessed score cannot pass public v2 verification.

The opt-in runner now requires source-start and run-visibility receipts; the scorer replays a sealed local score before recording and witnessing it. Public v2 issue verification also requires the committed manifest witness, and public score verification requires the exact score witness. `readWitnessedBoundLabelsWithPgV2` filters issues and scores by their DB witness times at an `asOfUtc` cutoff and reconciles exact retained files against DB-enumerated arms inside witnessed runs. Its denominator excludes published slots that never reached a run witness. `listPublishedSlotCensus` separately counts scheduled slots with manifest witness evidence and describes attempted, missed, and partial slots using retrospective DB timestamps; those attempt states are **not certified historical as-of states**, because later commits can change the apparent state of an earlier cutoff. Neither path makes chronological backtesting or a probability forecast eligible. The fresh runner checks for prior DB stages and exact-slot local start files before creating a new receipt; it refuses a partially committed slot without generating more local files. A separate opt-in `--recover-finalization <manifest-sha> <slot-id>` path can finish only a slot with four committed results, a committed source start, and exact retained local start/issue bytes. An issued arm must have a canonical issue time at or after the committed source start and a target equal to issue time plus its horizon. This audit checks persisted receipt chronology and exact bytes; it does not independently replay the underlying RPC captures. It confirms the run if needed and adds a run visibility witness before the earliest issued target. An existing valid witness returns without mutation. It never mints starts/results or recollects sources. Partial starts/results, missing source start, missing local bytes, or missed deadlines remain operational gaps. Neither the fresh preflight nor recovery audit is an exclusive cross-process claim. The migration has not been applied live.
