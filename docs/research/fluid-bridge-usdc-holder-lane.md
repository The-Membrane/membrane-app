# FluidBridge USDC holder callability lane

This local study is bound to the frozen Ethereum route `USDC → FluidBridgeAggregatorProxy [USDC]`, vault `0x273da948aca9261043fbdb2a857bc255ecc29012`, and USDC `0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48`. It assesses a same-holder USDC `withdraw(Q, holder, holder)` **eth_call**, not a mined transfer, bridge delivery, USDT conversion, or full exit. The existing direct-vault adapter marks implementation source attestation false.

`scripts/research/carry-fluid-bridge-usdc-holder.mjs --issue` chooses one common finalized block from configured Ankr and DRPC origins. It scans up to sixteen 64-block vault-share Transfer windows. If DRPC cannot answer an older range, a selected Ankr candidate needs an exact matching DRPC transaction receipt; any otherwise quiet window is then classified as unverified, never proof that no holder exists. The selected EOA's pinned share balance and `maxWithdraw` must agree on both origins. Five fixed USDC amounts (1%, 10%, 25%, 50%, 100% of the selected holder's current `maxWithdraw`, with zero/duplicates removed) are measured on both origins at the same block and issued with H1/H4/H24/H48/H168 targets. A failed or absent candidate becomes an attempt, not a success sample. One issue per 30-minute slot is allowed; repeats from one holder are correlated.

`--score` revisits the **same holder and exact raw Q** at the first due target it can process. It records later finalized-block callability only within a two-hour capture window; a missed window is censored. A provider or identity failure leaves an attempt for retry while the window remains open. Three private numbered hash chains hold issues, scores and attempts with no-overwrite, file and directory fsync, bounded reads, and a 1 GiB disk reserve. `--verify` returns route-level counts without holder, amount or exact issue time. The local hash chains and origin labels are not provider signatures.

Each issue seals the selected vault-share Transfer with canonical 32-byte amount and indexed addresses, its bounded 64-block query range, the matching second-origin log or exact transaction receipt, and their transaction/block hashes. Offline verification replays those relationships against the candidate holder and issue baseline. This is a locally captured source witness, not a provider-signed receipt or proof of completeness over older windows. Public episode counts include a unique-holder count because repeat issues for the same holder are correlated.

The USDC vault withdrawal is also the first leg of the tracked `USDT → FluidBridgeAggregatorProxy [USDC]` route. An observation of this first leg must not be counted as an independent USDT exit or as evidence of USDC-to-USDT conversion and delivered USDT.

The Mac jobs `com.membrane.carry-fluid-bridge-usdc-holder-issue` and `com.membrane.carry-fluid-bridge-usdc-holder-score` run every 30 and 5 minutes respectively via one shared lock.
