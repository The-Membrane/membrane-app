# scrvUSD issue-time horizon evidence

`scripts/research/scrvusd-exit-horizon-evidence.mjs` is a read-only research table over the verified prospective issue and score ledgers. Its production entry point is `readHorizonEvidence`, which calls `readEvaluation` before building the table. Up to 64 caller horizons are positive seconds no greater than the existing issue protocol maximum, and every horizon is measured from each issue's actual issuance time. The same issued observation can appear in multiple requested horizon columns; these columns are dependent views, not separate trials. An issue only enters a requested horizon's risk set when its originally issued follow-up horizon is at least that long. Shorter issues are counted as `notEnrolledForHorizon`; `allIssuedObservations` and eligible `issuedObservations` remain separate.

For each requested horizon, the table counts first sampled loss intervals whose end is at or before the horizon, intervals that straddle it, and intervals that start later. A sampled clean observation ending a right-censored trajectory is counted separately when its offset is before or at/after the horizon. Pending follow-up stays split into not yet due, requested horizon passed while a longer enrolled follow-up is still pending, open capture window, matured without a score, and unknown pending. The new passed-horizon cell is computed from the canonical issue time and requested horizon at the evaluation as-of; the upstream `not_yet_due` class refers to the issue's original target and cannot be reused after a shorter requested horizon passes. Exact-horizon pending rows retain the upstream due/capture/matured distinction. Missing, provider-ambiguous, ambiguous-censor, point-only, and malformed temporal evidence each remain separate. A negative pre-issue interval start is retained rather than rewritten as positive survival from issuance.

The table retains the evaluation's dependent components, counts all involved components, and separately counts components containing at least two eligible issues. A singleton component is not called an overlapping window; independent episode count stays `null`. The first-loss interval is open at its clean start and closed at its failed end: a horizon exactly equal to its start is classified as before the loss interval. A clean sample is evidence only at that sample, not throughout the preceding gap. A first sampled revert by a horizon does not establish exit ability at that horizon. This table is `research_only`, `forecastEligible:false`, and emits no probability or likely duration. No consumer should turn these counts into a depositor alert until independent outcomes, holdout performance, and the holder-executable route are established.

Run: `node scripts/research/scrvusd-exit-horizon-evidence.mjs 2026-09-28T12:00:00.000Z 3600 86400`. The local corpus began with four same-anchor NOW-origin issues on 2026-09-28 (1h, 2h, 24h, 7d). They are one dependent exposure cluster, with outcomes pending at issuance; the live table must be read afresh as subsequent captures and scores arrive.
