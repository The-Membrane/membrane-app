# scrvUSD target-window capture pass

This is an opt-in research capture pass for pending v1 and DB-witnessed v2 NOW-origin exit issues. Run `node scripts/research/scrvusd-target-window-capture.mjs --run` about every 10–15 minutes while an issue is within 30 minutes before its fixed target through 90 minutes after it. With no argument, the CLI is dry and writes nothing. It does not modify the hourly recorder schedule or create a forecast or alert.

The pass verifies retained issues, then records at most one new finalized quote checkpoint under the quote collector's lock and 1 GiB disk reserve. It chooses the quote that the immutable scorer would choose at that moment: nearest block timestamp to the target within ±30 minutes, with the same block/hash tie break and capture deadline. For each selected block (at most eight per pass), it checks or captures exact-block vault/target code and asks the predeclared holder observer to probe that exact block. The final report re-reads verified sources and marks a quote `paired` only when its holder probe has the issue's holder, amount, block identity, and on-time capture. It reports missing quote, holder, RPC, finality, or disk evidence as operational missingness. A later closer checkpoint can change the scorer's selected quote, so a later pass must check pairing again.

The pass uses its own non-expiring directory lock. A stale lock needs a manual audit before removal. V2 issues require `SCRVUSD_SCHEDULE_PUBLISHER_DATABASE_URL` and fresh committed schedule, attempt, and visibility witnesses; if no v2 issue is active, the DB connection is not used. The CLI uses configured `RECORDER_RPC_URL` hosts 0 and 1 for quote/code and holder calls. Provider errors and URLs are suppressed in CLI output. No historical target is backfilled: finalized quote capture is prospective, and the holder observer refuses a quote older than one hour. Code attestation refuses a quote older than two hours. A successful read-only simulation remains a discrete observation, not an executable transaction or guarantee of future exit.

The top-level pass status is `partial` whenever quote capture, code attestation, or holder probing fails, or when any active issue lacks a paired selected quote. `failureReasons` and `missingPairCount` summarize that incomplete capture alongside the per-stage details. `observed` means the pass captured its available discrete evidence; it is never a forecast-success label.

Before enabling a 10–15 minute cadence, restore the existing disk reserves and the authorized RPC network path. A missing pass or an unavailable capture stays in the cohort's missingness denominator; do not turn it into an exit failure or a confidence estimate.
