# Aave governance factual notice candidates

`readFactualGovernanceNotices(path)` reads the SHA-chained prospective queue journal through `readJournal()` and makes a pure, read-only projection. It performs no RPC, database writes, or notification sends. `projectVerifiedGovernanceJournal(journal)` is the pure reducer for an object already returned by the verified reader.

Each payload ID yields at most one candidate. The journal reader requires each event-touched payload/block to have one getter snapshot with the exact same block hash and timestamp. Event-block snapshots and repeated finalized-frontier rechecks preserve the first **local feature availability** time and update the latest observed lifecycle state. `firstQueuedLocalFeatureAvailableAt` is separate: an earlier creation observation cannot serve as the lead origin for later queue timing. It stays null until a queued state is locally observed. The candidate retains the controller, chain, latest block hash, and event block/transaction/log coordinates. A later recheck does not create a second notice. Regressing local clocks, reversed lifecycle states, inconsistent pinned blocks, and incorrect queue timing fail closed.

The onchain `queuedAt` and `delay` fields are observations from a block-pinned getter. `earliestExecutableAt = queuedAt + delay + 1` is derived from the published reference source's strict timestamp condition. The deployed implementation has **not** been attested, so this is labeled `reference_code_unattested`; `executionEligibility` remains `unclassified_code_unattested`. `reserveImpact` and `exitImpact` remain `unclassified`. No candidate is an exit-capacity forecast or a claim that execution will occur.

Coverage is `unavailable` for an empty journal or when the latest receipt is a provider failure, canonical conflict, or coverage limit. Previously observed candidates can remain visible with that unavailable status. A successful complete receipt covers observed payloads only; a single provider does not corroborate non-Created log completeness. Zero candidates therefore never means governance is quiet. `notificationEnabled` and `forecastEligible` are always false.

This is a research seam. Before user alerts, the deployed controller implementation and action call paths need verification, reserve/exit effects need explicit classification, and the event stream needs independent completeness checks. None of those gates is inferred from a payload title, function signature, or reference timestamp alone.
