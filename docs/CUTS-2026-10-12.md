### Restoring a single cut

- These shas revert cleanly on their own at the tip: **3, 6, 9, 10, 12**.
- The rest delete entries from the same shared lists as a later cut: robots.txt
  Disallow lines, Layout `EXECUTABLE_ROUTES`, HorizontalNav arrays, middleware
  `TOP_LEVEL_ROUTES`, and the ditto-gating mirror. A standalone `git revert <sha>`
  on one of these hits a small conflict in those files (cut 1: ditto-gating; 2:
  HorizontalNav, Layout, ditto-gating; 4 and 5: robots.txt; 7: Layout, ditto-gating;
  8: ditto-gating; 11: middleware, robots.txt). To resolve, keep the current list
  and add back the one route line the cut removed. The deleted files themselves
  never conflict.
- If you only need the files back: `git checkout pre-cut-2026-10-12 -- <paths from the Files removed column>`, then add back the ref lines by hand.
- To restore everything: `git revert --no-commit d166ef5b^..7df6e751` reverts the twelve cuts newest-first. This was verified conflict-free and yields a tree identical to `pre-cut-2026-10-12`. To restore a contiguous tail of cuts, revert newest-first down to the one you want, which also avoids the list conflicts above.

No permanent redirects were added for the cut routes. A 308 is cached by browsers,
so it would keep shadowing a route after a revert. The routes now 404, either through
middleware (top-level routes) or because no page matches.
