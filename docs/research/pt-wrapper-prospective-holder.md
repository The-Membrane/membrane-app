# Twyne PT wrapper: prospective holder assay

Frozen route: `USDe → AaveV3ATokenWrapper [PT-srUSDe-22OCT2026]`; wrapper `0x0af56afbddcb140323445bd7211ba90e54e5fd1c`; asset PT `0x59bc9fae5d62b19d4f8d07d758047acb9ee19d34`; Aave aToken `0x01e69a58ca3ddc695820ce6f66fbdf3fa55d0545`. The exact identity and implementation guards live in `lib/carry/twynePtExit.ts`.

The local lane `scripts/research/carry-pt-wrapper-holder.mjs` selects holders from the frozen August route cohort. V3 scans **all 16** frozen holders at one common finalized Ethereum block. Ankr and DRPC must agree on block hash, pinned account code and wrapper share balance for each holder; for a no-code address with at least ten raw share units they must also agree on `previewRedeem` for one tenth of those shares. Selection rotates through the frozen order from a recorded offset and takes the first qualifying no-code holder. A contract holder is never substituted. A scan with no qualifying no-code address records a typed `no_code_candidate_unavailable` attempt without an issue, including the full 16-holder witness and pinned block for offline negative-selection replay. The issue retains both origins' exact `0x` code result, the full bounded scan witness, the selected holder and its pinned block. Offline replay binds the stored selection order, code classification, holder kind, shares and preview, including against a SHA-resealed single-field forgery. It checks internal consistency, but the local seal cannot authenticate a coordinated SHA-resealed rewrite of the purported RPC observations without independent state proof. The Q ladder tests 1%, 10%, 25%, 50%, and 100% of that bounded PT preview. The same holder and raw Q values are re-assayed at H1/H4/H24/H48/H168. Late scores are censored only after both origins agree on a finalized block strictly past the deadline. Local SHA-chained issue, score, and attempt files are immutable and replayed by `--verify`; public counts omit holder identities. V3 also retains V2's seven deployment code hashes and strict replay of the wrapper, aToken, pool, YT, SY, expiry, maturity, decimals, status, and both withdrawal and redemption simulation fields.

The assay calls `withdraw(Q PT, holder, holder)` and `redeem` through `readTwynePtExit`. It measures **a counterfactual wrapper first leg**, not the borrower's authorized exit: the frozen cohort `owner` was copied from Aave's borrower address and is a Twyne collateral vault contract. A correct user-route assay starts with its `borrower()` controller and calls the collateral vault's `redeemUnderlying(shares, receiver)`, which handles reserved credit and EVC health checks before delivering PT. No wrapper call here proves mined PT delivery, controller authority, Pendle PT→SY, SY→USDe, or final USDe payout. `maxWithdraw` is not used as available capacity because this wrapper's implementation returns an unconditional maximum.

The first live V1 issue on 2026-10-01 sealed five Q cases for a frozen-cohort contract holder with 5.26542 wrapper shares. Fresh-eye review found that V1's offline verifier accepted SHA-resealed omissions of critical identity fields and did not store code hashes. V1 remains immutable **legacy evidence** and is excluded from validated outcome denominators. V2 uses a separate immutable ledger root and `holderKind: contract`; contract call successes are recorded as `contract_call_success_control_unassessed`. V3 uses another separate root and only issues for an observed no-code address. No deployed code does not establish EOA private-key control or transaction authority. A read-only two-provider probe at finalized block 26,097,011 found that **all 16 frozen cohort addresses had deployed code**, with seven holding positive wrapper shares; V3 therefore has no eligible cohort holder at that block. An older sampled 4,096-block Transfer range likewise found no no-code recipient among four distinct recipients, but is not a complete holder archive. The owner-to-user route graph needs verification before widening candidate discovery. No V2/V3 issue or future score has yet sealed. Even V3 call success remains simulated PT first-leg callability, not holder-executable delivery or final USDe payout. No outcome probability or restriction duration is calibrated.

Native local jobs: `scripts/carry-pt-wrapper-holder-tick.sh --issue|--score`, with corresponding `com.membrane.carry-pt-wrapper-holder-{issue,score}.plist` templates. The issue tick is configured for 30 minutes and the score tick for 5 minutes. Both remain stopped because the cohort assay targets intermediary contracts; the Mac disk reserve has since recovered. V1 and V2 roots remain untouched. At finalized block 26,097,075 the factory recognized all 16 cohort contracts and four of seven positive-share vaults had no-code `borrower()` controllers. The factory beacon's live Aave collateral-vault implementation reported `version() = 3`, while the publicly reviewed source returned 2; exact deployed-source semantics require verification before promoting a borrower-path assay.
