# R17 staging producer — Codex continuation, source draft

This producer stages issuance-time inputs only. It does not fit the R17 correction models, score them, select a model or authorize a reserve read. The earlier research checkout remains immutable. This is retrospective development feasibility work, not strict forward validation of a finalized model.

```text
280 admitted raw files → 277 original canonical keys
  → SHA256("Q26-R17-STAGING:" + canonical key), first 24, no resampling
  → raw OHLC → own-quarter mature HAR fit + own-series fH library
  → daily 00:00 UTC origins, 2022–2025 × H={6,12,24,72,168}
  → horizon-{H}.npz + provenance/counts; correction training is separate
```

The source adapters are `r12_tail.dev_specs/load_series`, `a6_touch.Prep6(with_fbL=False)`, `a2_touch.fhs_predict`, and `r16_dev.realized/load_volume/btc_lookup`. For quarter Q the original HAR regression includes only origins i with i+H≤Q; its library obeys the same maturity cutoff. Coefficients standardize that quarter's library and forecast rows. Only rows inside Q are emitted; later coefficients never overwrite earlier outputs. Proof records retain maximum actual regression/library label-end timestamps and coefficient/cutoff identities. This changes the earlier hash/time classifier's future-peer procedure; it does not establish new information or uncontaminated validation.

The target is min hourly low over the next H hours relative to the last completed close. The common prospective barrier grid is [-.40,-.20,-.10,-.05,-.02], transformed with log1p; probabilities must be nondecreasing. PRIMARY `label_valid` requires every future low finite and positive, full H-hour end observed, and valid origin spot. Missing future bars cannot establish a no-hit label. `legacy_label_valid` preserves the original tolerant depth availability; `future_missing_hours` records missing/truncated hours. Invalid labels are zero placeholders and must be ignored. Retain the already-computed complete-window future_log_min as float64, NaN for invalid labels. It is label-only future information, never an Xbase/Xshape feature or training covariate; retaining it permits an independently audited label threshold and future range research without restaging, not a new forecast claim. `issue_eligible` depends only on the known origin spot/start, independently of label availability; `p_fH_valid` separately describes baseline availability. The baseline library retains the original ≤floor(.05 H) null-hour rule, a recorded comparator limitation.

`Xbase` is exactly the 12 raw static representations: lsH,lsf,dm,wm,r24,r168,r720,dd720,rng24,lvol,btc_r24,btc_dm. It is not the full earlier GB feature design. `Xshape` adds D/W/M jump share J/RV and downside-minus-upside semivariance/RV from past completed bars. These are representations of the same OHLC, not observed future jumps. Past high/low extrema ignore nonfinite bars and are undefined only when the full trailing window is invalid (the legacy extrema rule, not the 5% HAR null rule). Volume means retain the original window null tolerance. Undefined/nonfinite values become NaN plus explicit missing flags; no learned imputation/scaling occurs here. Volume-loader None does not prove absent source data. Raw fH is float64; a separate logit margin uses clipping at [1e-6,1-1e-6] and records clipping. No infinities are admitted.

Schema per horizon: sid:int32,ts:int64,p_fH:float64[N,5],y:uint8[N,5],label_valid:bool[N],legacy_label_valid:bool[N],future_missing_hours:int32[N],future_log_min:float64[N],Xbase:float32[N,12],Xshape:float32[N,6],quarter_cutoff:int64[N],p_fH_valid:bool[N],issue_eligible:bool[N],Xbase_missing:bool[N,12],Xshape_missing:bool[N,6],base_margin:float64[N,5],base_margin_clipped:bool[N,5],fH_fallback:bool[N]. Feature/barrier names and units are in the manifest. Canonical SID→key identities are retained. Asset class is unknown without independently confirmed metadata; tickers do not justify excluding stablecoins or other heterogeneous series. The fixed sample is never silently replaced.

All 280 price pins and two previously admitted auxiliary pins are authenticated. Payload reads are limited to selected grid inputs, legacy chain-construction dependency inputs required for selected dev:ETH, and already-admitted BTC feature input. Chain construction loads other original chain assets internally; that is a declared legacy dependency, not extra training series. The exact allowed paths are frozen in the request. No new network input, neural weights or market acquisition is needed.

One series is held at a time; one horizon Prep6 at a time. Compact per-series/horizon staging shards preserve progress on failure; final files concatenate those daily shards by canonical SID/time and remove finalized shards. No hourly archive is persisted. Request limits are wall1200s, RSS1GB, free disk2GB, total output500MB. A fresh output directory is mandatory. Failure retains partial shards and a stage/error receipt, never retries with a different sample. Real execution is refused while request status is DRAFT. Source/tests/request and all input/runtime pins require parent review and a separate refutation before execution.
