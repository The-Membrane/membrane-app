# v2 as-of receipt boundary — minimal additive design

Status: the four-table as-of migration and audited DB adapter are implemented for offline research and wired into the v2 runner, scorer, public verifiers, and a separate witnessed label reader. The base migration also adds a post-commit manifest witness for the published-slot plan. None of these migrations is deployed to the configured database, and no existing v1 or v2 row is upgraded. The older v2 retrospective label reader still uses local issue and score clocks and remains ineligible for chronological backtesting. The witnessed reader filters retained local receipts by committed DB witness times and exactly reconciles DB arms inside witnessed runs; slots without a run witness remain outside that label denominator.

## Durable facts and transaction order

Add one narrow migration, gated on the existing schedule and attempt schema, with four append-only tables and four `SECURITY DEFINER` functions. Every function uses `search_path = pg_catalog`, fully qualified tables, fixed-scope validation, `clock_timestamp()`, and `txid_current()`; revoke `PUBLIC` execution and table access. The new tables are:

1. `scrvusd_now_source_starts(manifest_sha256, slot_id, floor_xid, source_start_at, source_start_xid, nonce_sha256)`, primary key `(manifest_sha256,slot_id)`. One source collection is shared by the four arms. `start_scrvusd_now_source(...)` reads the committed capture floor and confirmed four starts, requires a distinct XID and in-slot DB clock, then inserts the server-timed start. The adapter commits and reads it back in a **new** transaction before the runner calls any RPC. Runner source receipts carry the nonce and bind exact response hashes. This is an operational ordering check, not independent proof that local RPC collection actually started then.
2. `scrvusd_now_run_visibility(manifest_sha256, slot_id, run_visible_at, witness_xid)`, primary key `(manifest_sha256,slot_id)`. `witness_scrvusd_now_run(...)` reads the committed four-result run confirmation and its exact arm rows, requires a distinct XID from the run confirmer, then stamps `run_visible_at` **after** that read. Require this witness before the earliest issued target. The current `confirmRun` already reads back after its commit but does not persist a timestamp of that read (`scripts/research/scrvusd-now-schedule-db.mjs:357-372`). A `run_confirmed_at` stamped inside the confirming transaction alone cannot certify historical availability if its commit happened later (`scripts/apply-scrvusd-now-schedule-ddl.mjs:477-509`).
3. `scrvusd_now_scores(manifest_sha256, slot_id, horizon_seconds, issue_logical_sha256, issue_physical_sha256, score_filename, score_logical_sha256, score_physical_sha256, score_payload, score_recorded_at, score_xid)`, primary key by arm, unique score hashes. `record_scrvusd_now_score(...)` reads the committed issued arm and run visibility, checks the exact v2 issue refs, verifies canonical score payload bytes and logical/physical SHA, and rejects a different retry. No local scored timestamp can substitute for `score_recorded_at`.
4. `scrvusd_now_score_visibility(manifest_sha256, slot_id, horizon_seconds, score_visible_at, witness_xid)`, primary key by arm. `witness_scrvusd_now_score(...)` reads the committed score row in a **different** transaction, checks the exact bytes and score/issue binding, then stamps `score_visible_at` after its read. The score can have been committed by the witness time even if the witness itself commits later. Readback in another transaction establishes that the witness row eventually committed. A present local score with no witness makes the public verifier fail closed.

The existing attempt sequence is four arm starts → distinct-transaction start confirmation → distinct-transaction capture floor → local source collection → four result rows → distinct-transaction run confirmation (`scripts/apply-scrvusd-now-schedule-ddl.mjs:266-509`; `scripts/research/scrvusd-now-slot-runner.mjs:154-270`). Insert source start **after the committed capture-floor readback and before** `collectSources` (`scripts/research/scrvusd-now-slot-runner.mjs:168-188`). Insert run visibility **after** `confirmRun` commits. A run witness may be too late; then that slot stays outside certified as-of enrollment, with no backdating. For each score, keep local atomic file creation, then record its exact canonical bytes in the score table, commit, witness in a new transaction, and read back. A crash between steps leaves an explicit unconfirmed state; retry only an exact byte match, never replace a conflicting row.

The role used for the new functions must have `SELECT` on these four tables and `EXECUTE` on these four functions, but no direct `INSERT/UPDATE/DELETE/TRUNCATE`, no table/function owner membership, no superuser/createrole/bypass privileges, and no grants to `PUBLIC` or another role. Extend the existing dedicated-role audit (`scripts/apply-scrvusd-now-schedule-ddl.mjs:637-710`) to cover every new table and function. A separate score-writer role would reduce the exposure of the in-slot attempt privileges held by a long-running scorer; if one role is retained for the minimal first migration, its credential must be isolated from general app traffic and rotation is required before production use.

## Read/query path

The PostgreSQL adapter must fetch the run witness and score witness in a fresh audited read-only transaction, with exact payload SHA checks. The issue verifier still replays retained source bytes and the four-arm DB proof (`scripts/research/scrvusd-bound-issue-verifier.mjs:33-275`). The score verifier still replays the sealed source snapshot (`scripts/research/scrvusd-bound-exit-forecast-score.mjs:65-130`). Bracket both asynchronous passes with the existing exact filename/hash file-set comparison (`scripts/research/scrvusd-bound-prospective-exit-labels.mjs:39-49`).

For a requested historical `asOfUtc`, admit a scheduled issued arm only when its **run visibility witness** is present and `run_visible_at <= asOfUtc`; do not infer that from `issuedAtUtc` or `run_confirmed_at`. Admit a score only when its exact DB payload and **score visibility witness** match the replayed local file and `score_visible_at <= asOfUtc`; do not infer that from `scoredAtUtc`. A later witnessed score is indistinguishable from no certified score at that cutoff. A present local score without a witness fails the public read instead of becoming an outcome. Preserve duplicate-arm and exact issue-reference checks, and keep v1 separate. The witness certifies availability by its timestamp, which may be later than actual availability; `targetUtc - runVisibleAtUtc` is a conservative minimum remaining lead. The retained-file reader cannot prove full DB cohort completeness until every DB arm and score is enumerated and reconciled.

The run witness necessarily follows local issue creation. A chronological study must use `runVisibleAtUtc` as the decision availability time and report each arm's remaining lead to its fixed target. The `1h` arm name describes a target one hour after local issue time; it does not establish one hour of user-visible lead after the witness. See `scrvusd-v2-live-cohort-runbook.md`.

## What these receipts still cannot prove

- `start_scrvusd_now_source` proves a committed DB gate existed before the honest runner proceeded. A locally controlled collector can still fetch RPC data before the gate, then claim a later `captureStartUtc`. Independent source timing needs a controlled RPC gateway that refuses calls without the committed nonce and emits a server-timed signed request/response digest (or equivalent provider attestation). Bind its digest to quote, holder, and code-attestation rows; only then promote source acquisition chronology beyond `self_reported`.
- Database witness time establishes that an exact score was committed by that time; it does not prove that an alert was delivered to a user, that a holder could execute continuously, or that the score was calibrated. Those require separate delivery receipts and prospective outcome evaluation.
- Old local issue/score files and current DB run rows cannot be retroactively assigned historical visibility witnesses. Their labels stay retrospective. If the DB role/schema is unavailable, do not synthesize the witness from filesystem metadata or local clocks.
