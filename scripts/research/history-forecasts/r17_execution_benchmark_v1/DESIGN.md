# DRAFT: serial-worker execution benchmark

No benchmark has run. Parent source review, tests and a separately reviewed outer launch guard are required before execution. No market inputs or outcomes are used. No frozen R17 files change.

Compare three fresh spawned processes (one for each linear/base/shape fit) against one persistent serial process receiving the same three tasks. Every task calls the actual SHA-pinned v3 `fit_predict` with fresh local model state, the original 128 rounds, seeds, margins, median imputation and linear scaling. The source module is imported without its CLI and without bytecode writes. Both paths explicitly import XGBoost before the ready message. No model state or preprocessing statistics transfer between tasks. There is only one heavy worker at any time.

The fixed seed1701 fixture has 10000 training origins expanded to 50000 rows and 1000 evaluation origins expanded to5000 rows. Base features12, shape features6, barrier log feature1,3% deterministic missingness. Complete monotone synthetic labels have a small state signal. This is one quarter-sized upper-middle workload, below the frozen40000-origin cap. It is not evidence about full40000-origin throughput, market learning, accuracy or GPU benefit. Input arrays are approximately1.5MB; expanded/imputed training arrays are approximately23MB at shape width, excluding optimizer/native overhead. The whole parent+worker census cap remains1000000000bytes. Fresh-first mode ordering confounds filesystem cache/thermal effects, so any speed ratio is descriptive for this single order, not a robust general speedup estimate.

Reported phases: parent spawn-to-ready (includes spawn/interpreter/module startup), child pinned-source imports, child XGBoost import, send-to-child-receive IPC, exact feature expansion, instrumented exact imputation functions, whole `fit_predict`, and its remainder excluding timed imputation. That remainder includes linear scaling, fitting and prediction. It must not be labeled pure training time. Result-return IPC and parent task roundtrip are also reported. Timers wrap and return exact functions without changing results. Each arm must reproduce its whole5000-element float64 vector bitwise, with raw-array SHA256 and maximum difference0. No tolerance fallback is allowed. Fresh model state follows the frozen function's local model construction; no persistent production integration is proposed.

The parent polls numeric-only `/bin/ps` metadata, summing its own RSS, every owned descendant (including startup children and the resource tracker), and every member of the worker's new process group. Unknown owned RSS fails closed, never becomes zero. Probe rc/malformed/missing parent fail closed. The observer's short-lived subprocess is excluded from the workload measurement and its overhead is not claimed zero. Samples are observations, not a hard memory maximum. Disk reserve2000000000bytes and total deadline60seconds are checked during polling. TERM then KILL targets the entire worker group even if the leader has exited, followed by a no-live-member census. Partial failure receipts survive. Fixed outputs are JSON only, no input/prediction arrays are persisted.

## Outer admission draft added after review

`outer_guard.py` now implements the independent stdlib watchdog. It launches the benchmark in a new session, polls its entire descendant tree and retained owned process groups, and accounts for its own parent RSS. Because fit workers create sessions, `benchmark.worker` now journals its PID/PGID in one atomic append before importing the scientific source. The outer observer retains all journaled groups even if their leader exits before a census. Every scientific function remains imported unchanged; the worker addition is ownership metadata only. The observer process is explicitly excluded. Unknown owned RSS fails closed rather than being measured as zero. Every known subtotal is checked before unknown handling. The wrapper terminates all owned groups and verifies a final no-live census even after benchmark leader exit. Output logs and partial receipts survive failure. Whole-job60seconds includes benchmark startup/import/IPC and cleanup; cleanup may run beyond the deadline to reap children, which yields a FAILED receipt, never an admitted successful run. This is sampled memory enforcement, not proof of an instantaneous hard kernel memory ceiling. Stdlib watchdog startup before its main execute entry is outside its reported clock.

Fresh launch paths are fixed by the admitted request; no READY request is created by this draft. Tests include timeout/blocked child and leader-exits/new-session-descendant cleanup using only tiny synthetic subprocesses, plus metadata and pin failures. These tests have not yet run by the author. Parent must test source and fresh-refute containment before any benchmark execution. Existing first draft/pins remain preserved in source-pins.history-v1.json; the replacement source-pins.DRAFT.json captures reviewed changes, runtime/native static pins and a DRAFT admission skeleton.
