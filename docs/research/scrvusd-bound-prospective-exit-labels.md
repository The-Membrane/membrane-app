# Bound scrvUSD exit labels (research v2)

`scripts/research/scrvusd-bound-prospective-exit-labels.mjs` reduces scheduled v2 issue and score receipts to a read-only table. Call `readBoundLabelsWithPgV2` with a PostgreSQL pool, an `asOfUtc` ISO timestamp, and the source roots. It uses the separate bound issue and score directories in `scrvusd-bound-paths.mjs`; v1 manual issues never enter its denominator.

Each issue is verified afresh against audited PostgreSQL publication, four-arm run, source-start, and run-visibility readbacks. Existing v2 scores are replayed afresh and require an exact committed score-visibility witness; the reader checks the issue and score filename and physical SHA file sets before and after these asynchronous checks. Exact duplicate `(manifest SHA, slot ID, horizon)` arms fail, while different valid slots can share an anchor block and horizon. Scores must refer to the exact issue filename, logical SHA, and physical SHA.

The table keeps `pending` (capture deadline open), `matured_unscored` (deadline closed without a visible score), scored `missing` (no selected checkpoint), `ambiguous` (such as provider ambiguity), and `observed` distinct. A future score is invisible at a historical as-of time. Missing or ambiguous evidence does not count as an exit failure. Forecast probability and likely duration remain null; no user alert is issued.

Historical `asOfUtc` views are retrospective reconstructions from the ledger verified now. The new database run and score visibility witnesses exist for newly recorded v2 rows, but this label reader does not yet filter them by the requested historical cutoff; its inclusion rule still uses local issue and score clocks. The reader sets `historicalAvailabilityCertified:false` and `chronologicalBacktestEligible:false`; use it to inspect outcomes, not to claim a clean historical backtest.

## Witnessed historical as-of view

`readWitnessedBoundLabelsWithPgV2` is a separate read-only API and schema (`scrvusd-bound-prospective-exit-labels-witnessed-v1`). It first runs fresh public PostgreSQL issue verification and full score replay, including the required current score visibility witness. It reads the exact audited run and score visibility receipts while checking that issue and score filename, logical SHA, and physical SHA sets remain stable across all asynchronous work. An absent or unwitnessed retained issue or score fails closed; it is not silently counted as missing or pending.

A witnessed issue enters the historical cohort only when `runVisibleAtUtc <= asOfUtc`. A later run witness leaves no issue row, timestamp, or excluded-issue count in the as-of output. A retained score enters only when its exact `scoreVisibleAtUtc <= asOfUtc`. A score witnessed later has exactly the same as-of output as no certified score: `pending` before the capture deadline or `matured_unscored` afterward, with no future score timestamp, result, reference, or distinct future-score count. A present-day unwitnessed file fails the public reader instead of entering either state. Missing, ambiguous, and observed outcomes remain separate after score visibility.

Each admitted row reports `certifiedMinimumPublicationLeadSeconds = targetUtc - runVisibleAtUtc`, the conservative lead from the committed run witness to the target. This is a witness-defined publication lead, not the time an individual user had to act. `baselineSampleAgeSecondsAtWitness` measures from the locally reported holder capture end to that witness. The baseline was sampled before the witness; `currentAtDecision` is always `unverified`. Source capture times remain self-reported even when constrained by a committed source-start receipt.

The reader now queries `listWitnessedCohort({asOfUtc})` in an audited database snapshot even when the local directories are empty. It reconciles every DB-issued arm visible by the cutoff with an exact retained issue filename, logical SHA, physical SHA, and payload; it does the same for each DB score witnessed by the cutoff. A missing or mismatched local file, or an extra locally visible row absent from the DB census, fails closed. The output's `armDenominators` counts all four arm statuses (`issued`, `abstained`, `failed`, `unknown`) for DB-witnessed runs, separately from the `issued` label risk set. Later DB or local score receipts do not enter those historical counts or reveal future metadata.

`witnessedRunCohortComplete:true` means the retained local files exactly match the DB census of runs witnessed by this cutoff. `scheduledSlotCohortComplete:false` and `fullCohortComplete:false` remain: published manifest slots whose runs never reached a visibility witness are outside that DB query. `historicalAvailabilityCertified:false` and `chronologicalBacktestEligible:false` remain because source acquisition is not independently timed and adequate realized outcomes are absent. No calibrated forecast or continuous-exit claim follows. Existing retrospective `readBoundLabelsWithPgV2` and its schema remain unchanged.

This reader does not establish continuous ability. Source `captureStartUtc` values are local and self-reported even when they are consistent with a database source-start receipt. The helper `labelsFromVerifiedBoundRowsV2` is a deterministic reducer for synthetic tests; only the PostgreSQL reader performs the fresh linkage and score checks.
