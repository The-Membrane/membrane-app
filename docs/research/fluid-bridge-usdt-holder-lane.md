# FluidBridge USDT route: prospective holder first leg

The frozen Ethereum route is `USDT → FluidBridgeAggregatorProxy [USDC]`. Its pinned first-leg vault is `0x273da948aca9261043fbdb2a857bc255ecc29012`; the vault asset is USDC `0xa0b86991c6218b36c1d19d4a2e9eb0ce3606eb48`, while the requested final payout asset is USDT `0xdac17f958d2ee523a2206206994597c13d831ec7`. The prospective assay is a read-only same-holder USDC `withdraw(Q, holder, holder)` call against that vault. It does not establish a mined USDC transfer, USDC→USDT conversion, USDT receipt, or complete holder exit. The direct-vault adapter reports implementation source attestation as false.

`scripts/research/carry-fluid-bridge-usdt-holder.mjs --issue` chooses a finalized block agreed by the configured Ankr and DRPC origins, then scans bounded vault-share Transfer windows for an EOA holder with a nonzero balance and `maxWithdraw`. The selected Transfer must contain an ABI-valid 32-byte value. If the secondary origin cannot serve an older log range, an exact transaction receipt must attest the selected Transfer; this fallback proves that **selected candidate only**, not completeness of the range. An empty range without two-origin agreement remains unverified. The private issue ledger retains a bounded selected-log witness from each origin (or the matching receipt log plus transaction/block identity); offline replay binds both to the candidate holder, transaction, block, and scan window. Both origins must agree on pinned entitlement and five bounded USDC Q values (1%, 10%, 25%, 50%, and 100% of current `maxWithdraw`, with zeros and duplicates removed). Each issue fixes the holder and Q for H1/H4/H24/H48/H168 scoring. One issue per 30-minute slot is allowed; repeated observations of one holder are correlated.

`--score` reassays the same holder and Q at a common finalized block in a two-hour target window. A missed window is censored only when both origins agree on a finalized chain timestamp beyond the deadline. Source failures remain attempts. Separate private, numbered, SHA-linked issue, score, and attempt ledgers use no-overwrite writes, file and directory fsync, bounded reads, and a 1 GiB disk reserve. `--verify` publishes coarse counts without a holder address, amount, or exact target time. Local hashes and origin labels are not provider signatures.

The Mac issue and score jobs run every 30 and 5 minutes under one route-specific lock. This lane must remain distinct from the USDC FluidBridge lane even though both share the same USDC vault: its subject and final payout obligation are USDT. Their USDC vault first-leg observations are **shared exposure**, not independent route-level evidence; counting an identical holder/Q/time assay twice would inflate a forecast sample. Neither lane's first-leg `eth_call` is a validated holder-exit forecast. A later completion study must attest the conversion and delivered USDT before treating this route as end-to-end forceable.

At 2026-10-01 setup, one manual issue and one native issue tick each sealed `source_unavailable`; offline replay reports two attempts, zero issues, and zero scores. The native issue job exited 0 and both jobs remain loaded. A separate bounded two-origin finalized-head probe returned HTTP request errors from both configured origins in the current sandbox. These attempts do not indicate that a holder could or could not exit.
