# Witnessed scrvUSD first sampled loss by selected H

`scripts/research/scrvusd-witness-first-loss.mjs` is a separate research reducer for the scheduled v2 scrvUSD exit cohort. Its public entry point, `readWitnessedFirstLossWithPgV2`, first calls `readWitnessedBoundLabelsWithPgV2`. That reader reconciles retained issue and score receipts with the PostgreSQL witness and four-arm run cohort. `buildWitnessedFirstLoss` is pure and does **not** authenticate caller-supplied labels; production or published research must use the public reader.

The caller selects one or more horizons H from one second through `MAX_HORIZON_SECONDS` (one year). An issued arm enters H's descriptive path risk set when its certified remaining publication lead, `targetUtc − runVisibleAtUtc`, is at least H. An arm scheduled for two hours can therefore contribute witnessed path evidence for a selected one-hour H; an arm with less than one hour of remaining lead cannot. The existing witnessed evaluator validates **all issued rows** before this alternate selection. It retains its separate exact-target point evaluation, but that rule is not used to select first-loss paths. Non-enrolled issued arms are explicitly counted as insufficient remaining lead. The full DB-witnessed `issued`, `abstained`, `failed`, and `unknown` four-arm denominator remains visible. Runs without a witness and scheduled slots without a run remain outside this cohort.

For an eligible arm, the first sampled loss interval is compared with both the run witness and the exact selected H endpoint. The classes distinguish loss entirely before witness, an interval straddling witness, definite post-witness first sampled loss by H, an interval straddling H, and first sampled loss later than H. Endpoint equalities are explicit: an interval ending at witness is pre-witness; one ending at H is by H; one starting at H is later than H. A clean sampled-success right censor covers H only if its last clean success block timestamp reaches H. Otherwise it is censored before H. An ambiguous trajectory stays ambiguous. A point result at the scheduled target is **never** substituted for a first-loss path, even if the point is a revert.

`scoreStatus` and `pointStatus` remain separate fields, so missing and ambiguous checkpoints are visible even if a prior first-loss interval exists. Pending arms distinguish whether selected H has not yet elapsed from H elapsed while the longer scheduled arm awaits a score; neither is a success or failure. Matured unscored arms have a separate class. Every row retains the exact issue, arm, anchor, holder, amount, and route identity. Overlapping capture windows or common anchors remain dependent components; their count is not an independent episode count.

The source baseline is a pre-witness sampled observation. Current ability at the run witness is `unverified`, and sampled success does not establish continuous holder exit ability. The result does not give a probability, likely duration, or alert. Source capture times and DB-witness coverage do not establish a complete scheduled-slot cohort or a prospective chronological backtest. This classification is descriptive evidence toward future calibration, not a user-facing forecast.
